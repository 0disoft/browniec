Brownie C에는 C처럼 메모리를 직접 주무르는 포인터(`ptr`)도 없고, Fairy C처럼 `cleanup`을 붙이는 사용자 `resource`도 없습니다. 대신 **크기가 정해진 배열·레코드**, **바이트 리터럴**, 그리고 **안전 검사가 붙은 슬라이스(`ref u8[]`, `ref mut i32[]`)**로 데이터를 다룹니다.

## 1. 구조체 값 복사와 고정 배열 아레나

- **평범한 `struct`**: 값 자체를 복사해서 주고받습니다. 안에 `cleanup`이 필요한 자원이 들어갈 수 없으므로 이중 해제 걱정 자체가 없습니다.
- **고정 배열 (`T[N]`)**: 배열 하나에 최대 **4096개**까지 요소를 담을 수 있고, 실행 시 전체가 **65,536바이트(64 KiB)** 공간 안에서 관리됩니다.

배열이 들어 있는 프로그램을 돌릴 때 한 가지 꼭 기억해 둘 점이 있습니다. VM이 실행을 시작하면서 이 64 KiB 배열 공간을 준비하는 데 **65,537 Fuel**을 미리 씁니다. 그래서 배열이나 레코드가 들어간 코드를 돌릴 때는 `--fuel 100000` 또는 `--fuel 1000000`처럼 충분한 예산을 주어야 합니다.

## 2. 바이트·텍스트 리터럴과 슬라이스 뷰

`b"..."` 바이트 리터럴과 `"..."` 문자열 리터럴을 만들 수 있고, `ref u8[]`나 `ref mut i32[]` 같은 슬라이스로 배열의 일부 또는 전체를 함수에 빌려줄 수 있습니다. 실행할 때 인덱스 범위가 넘어가면 바로 에러(`bounds`)로 막아 줍니다.

```c
module main;

fn i32 main() {
    var u8[3] bytes = [128; 3];
    bytes[0] = 234;
    bytes[1] = 176;
    if (text::valid_utf8(bytes)) { return 42; }
    return 0;
}
```

다른 함수가 배열 내용을 고쳐 쓰게 하고 싶다면 `ref mut` 슬라이스로 빌려주고, 그 함수 안에서 또 다른 도우미 함수로 넘겨줄 수도 있습니다(`examples/mutable-slice-reborrow.brc`).

```c
fn void touch(ref mut i32[] values) {
    values[0] = 42;
}

fn i32 forward(ref mut i32[] values) {
    let ref mut i32[] alias = ref mut values;
    touch(alias);
    return alias[0];
}
```

컴파일러가 "같은 배열을 두 군데서 동시에 수정하려고 겹쳐 빌리지 않았는지" 실행 전에 미리 확인해 줍니다.

## 3. 참고: 저장소 내부 `Buffer` 기능과의 차이

저장소 문서에는 동적으로 크기를 늘리는 `Buffer`(`bytes::empty`, `bytes::copy` 등) 얘기가 자주 나오지만, 이것은 현재 **저장소 내부 테스트 경로에서 개발 중인 기능**입니다. 지금 공개 `browniec` CLI에서는 고정 배열, 구조체, 바이트/텍스트 리터럴, 슬라이스까지 사용할 수 있습니다.
