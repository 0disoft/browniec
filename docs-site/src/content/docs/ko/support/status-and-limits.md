Brownie C는 가볍고 예측 가능한 임베디드 규칙 실행을 위해 크고 작은 제한을 의도적으로 두고 있습니다. 현재 단계에서 동작하는 범위와 한계는 다음과 같습니다.

> **검증 기준**: `2026-11-16` · 커밋 [`f5e13f9`](https://github.com/0disoft/browniec/commit/f5e13f9)

## 현재 공개 CLI에서 지원되는 것

`browniec --version --json`에서 확인되는 `"core": true`는 현재 공개 CLI의 실험 부분집합(스칼라, 고정 배열 읽기·쓰기·복사, 평범한 `struct`, 바이트/텍스트 리터럴, 스칼라/바이트 슬라이스)이 동작함을 뜻합니다. 아직 전체 언어 사양 완성이나 프로덕션 인증을 뜻하지는 않습니다.

## 단일 파일 용량 한계

| 항목 | 현재 상한 |
| --- | --- |
| 소스 파일 | 1개 `.brc` 파일, 최대 `4,096`바이트 UTF-8 (`1,024` 토큰) |
| 진입 함수 | 인자 없는 `fn i32 main()` 고정 (외부 `--input` 바이트 전달 미구현) |
| 함수·명령어 | 함수 `16`개, 전역 레지스터 `128`개, VM 명령 `256`개 |
| 호출 스택 | 최대 `32`프레임 |
| 배열·레코드 | 사이트 `16`개, 배열당 최대 `4,096`개 요소, `64 KiB` 통합 아레나 |
| Fuel 예산 | 기본 `256`, 최대 `16,000,000` |

## 플랫폼 및 미구현 기능

- **Windows 11 x64 (`MSVC`)**: 주 개발·실행 환경입니다.
- **Linux**: `toolchain.json`에 크로스 빌드된 `fairyc` 정보가 들어 있지만, 실제 Linux 호스트에서의 빌드와 `browniec` 실행은 아직 검증되지 않았습니다.
- **미구현 상태**: `--isolated` OS 워커 격리(`restricted: false`), C 임베딩 SDK(`embed: false`), 다중 파일 `--project`, 게스트 `--input`/`output_b64`, 내부 `Engine`/`Buffer` CLI 호출은 아직 준비 중입니다.
- **영구 제외 기능**: JIT, 가비지 컬렉션, 부동소수점(`f32`/`f64`), 원시 포인터(`ptr`), 임의 C FFI, 스레드는 설계상 포함하지 않습니다.
