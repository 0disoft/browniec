큰 애플리케이션 안에서 사용자가 넘긴 **짧은 규칙이나 바이트 패턴 검사 로직**만 안전하게 실행하고 싶을 때가 있습니다. 일반 시스템 언어로 바로 컴파일해 돌리자니 파일이나 네트워크를 건드릴 위험이 있고, 무한 루프에 빠지면 호스트 프로그램까지 멈출 수 있죠.

Brownie C는 바로 이런 용도를 위해 **기능을 의도적으로 좁히고, 실행량을 Fuel로 제한한 미니 언어와 VM**입니다.

## Brownie C의 특징

- **Fairy C를 닮은 C 스타일 문법**: `let`/`var`, `if`/`switch`, `for`/`while`, `struct`, `Option`/`Result` 같은 익숙한 문법을 씁니다.
- **위험한 기능은 아예 뺐습니다**: 원시 포인터(`ptr`), 임의 C 호출(`extern C`), 사용자 `resource`, 부동소수점, 가비지 컬렉터가 없습니다.
- **실행 전 검사 + Fuel 계량**: 배열 인덱스 범위와 슬라이스 빌림 규칙을 실행 전에 검사하고, VM에서는 `--fuel` 토큰 수만큼만 돌린 뒤 초과하면 깔끔하게 중단합니다.
- **`main()`의 반환값은 결과 데이터**: 게스트 코드가 `return 77;`을 반환하면 프로세스 종료 코드가 77이 되는 대신, 실행 결과 데이터(`return_i32=77`)로 돌려받습니다.

## Lua, Python 같은 인터프리터 언어와 무엇이 다른가요?

호스트 프로그램 안에서 작은 로직을 돌린다는 점에서는 Lua나 Python과 목적이 비슷하지만, 언어 성격은 정반대에 가깝습니다.

- **실행 전에 타입·분기·빌림을 검사합니다**: Lua나 Python은 실행 중(`nil`/타입 오류)에 문제가 드러나는 동적 언어이지만, Brownie C는 정적 타입(`i32`, `u8`, `bool` 등)과 `switch` 누락 검사, `ref`/`ref mut` 빌림 규칙을 **실행 전에 먼저 확인**합니다.
- **가비지 컬렉터(GC)·부동소수점·기본 I/O가 없습니다**: 범용 스크립트 언어와 달리 GC나 실수(`float`), 임의의 파일·네트워크 호출 기능을 넣지 않아 규칙 계산이 단순하고 예측 가능합니다.
- **연산 예산(Fuel)이 기본 내장되어 있습니다**: Lua/Python에서 무한 루프를 막으려면 별도 훅이나 감시 장치를 붙여야 하지만, Brownie C VM은 명령마다 `--fuel`을 차감해 예산이 끝나면 멈춥니다. (다만 Fuel은 연산 횟수 제한일 뿐 OS 시간 제한이나 보안 샌드박스가 아닙니다.)
- **용도와 성숙도 차이**: Lua와 Python이 방대한 라이브러리와 성숙한 임베딩 API를 제공하는 범용 스크립트 언어라면, Brownie C는 현재 단일 `.brc` 파일(최대 4096바이트)로 짧은 규칙·바이트 검사를 돌리는 데 초점을 둔 초기 구현입니다.

## 현재 쓸 수 있는 범위와 개발 중인 부분

현재 공개 `browniec` CLI에서는 단일 `.brc` 파일(최대 4096바이트)에 대해 `check`, `run [--fuel N]`, `inspect --ir` 명령을 바로 실행할 수 있습니다. 스칼라 연산, `Option`/`Result` 분기와 `?` 전파, 고정 배열(`T[N]`), 평범한 `struct`, 바이트·텍스트 리터럴, 슬라이스(`ref u8[]`, `ref mut T[]`) 문법을 다룰 수 있습니다.

Windows에서는 단일 파일 스칼라 `check`와 `run`을 AppContainer/Job으로 격리할 수 있습니다. 격리 지원 범위 확대와 C 임베딩은 각각 `restricted: false`, `embed: false`로 표시합니다.
