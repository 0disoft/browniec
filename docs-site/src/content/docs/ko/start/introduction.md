Brownie C는 **Fairy C**로 구현 중인 임베디드 규칙·바이트 변환 언어 및 VM 런타임입니다. 파일시스템, 네트워크, 임의의 C 함수 호출에 대한 암묵적 권한 없이 엄격한 컴파일·실행 예산 아래 작은 결정적 프로그램을 검증하고 실행하는 것이 목표입니다.

## 핵심 특징

- **실행 전 다단계 검증**: 소스 문법, 타입, 배열·슬라이스 빌림 규칙, 내부 바이트코드 불변식을 실행 전에 검증합니다.
- **검사된 산술과 경계 확인**: 정수 오버플로, 0으로 나누기, 인덱스 범위 초과는 호스트 프로세스를 망가뜨리지 않고 정의된 오류 종류로 종료됩니다.
- **Fuel 기반 연산량 계량**: `--fuel` 예산으로 명령어·배열·레코드 연산량을 결정적으로 제한해 무한 루프나 과도한 작업을 중단시킵니다.
- **데이터로서의 반환값**: 게스트 `main()`의 반환값(`return_i32`)은 결과 데이터일 뿐이며, 프로세스 종료 코드(`0` = 정상 완료)와 분리되어 있습니다.

## Brownie C와 Fairy C의 차이

| 구분 | Brownie C (`.brc`) | Fairy C (`.fy`) |
| --- | --- | --- |
| 성격 | 임베디드 규칙·바이트 변환 언어 + VM | 네이티브 시스템 프로그래밍 언어 |
| 실행 방식 | `browniec` 내부 검증기 + 레지스터 바이트코드 VM | C11 백엔드를 거쳐 네이티브 실행 파일 생성 |
| 구현 언어 | Fairy C로 작성 | Go 기반 Stage 0 컴파일러 |
| OS·C ABI 접근 | 불가 (`ptr`, 임의 FFI, 사용자 `resource` 제외) | `unsafe extern C fn` 및 표준 라이브러리 지원 |
| 실행 제한 | 명시적 `--fuel` 예산(기본 256, 상한 16,000,000) | 네이티브 OS 실행(VM Fuel 계량 없음) |

## 공개 CLI, 내부 Engine, 설계 목표 구분

저장소를 볼 때는 다음 세 범주를 명확히 구분해야 합니다.

1. **현재 공개 CLI(`browniec`)에서 사용 가능한 기능**:
   - 단일 `.brc` 파일(UTF-8 최대 4096바이트)에 대한 `check`, `run [--fuel N]`, `inspect --ir` 및 `--json` 출력.
   - 인자가 없는 `fn i32 main()` 진입점.
   - 제한된 스칼라, `Option`/`Result` 검사 및 `?` 전파, 고정 배열(`T[N]`), 평범한 `struct`, 바이트/텍스트 리터럴, 스칼라·바이트 슬라이스(`ref u8[]`, `ref mut u8[]`).
2. **내부 구현만 존재하는 기능 (공개 CLI 미노출)**:
   - 내부 `Engine` / `Instance` 단계 실행, 게스트 `Buffer` 할당, 다중 소스 프로젝트 컴파일, 호스트 와이어 코덱 등은 저장소 내부 모듈과 테스트 하니스에만 존재합니다. 현재 공개 CLI에서 `Engine`이나 게스트 `Buffer`를 직접 호출할 수는 없습니다.
3. **아직 구현되지 않았거나 계획 단계인 기능**:
   - `--isolated`(AppContainer/Job 워커 격리), `--project`/정책/권한 파일 로더, 게스트 `--input` 전달, 게스트 출력 싱크, C 임베딩 API(`restricted: false`, `embed: false`로 보고되며 C ABI도 부트스트랩 심볼 `bc_get_abi_info_v2` 테스트 수준만 존재).
   - 특히 **Fuel은 연산 횟수 계량기일 뿐이며, 실제 시간 제한(타임아웃)이나 OS 수준 보안 격리가 아닙니다.**
