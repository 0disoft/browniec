Brownie C에서 `browniec run`을 돌릴 때 `--fuel N` 옵션을 자주 보게 됩니다. 쉽게 비유하자면 **VM이 명령어를 실행할 때마다 내는 토큰**(선불 충전 금액)입니다.

## Fuel이란 무엇이고, 무엇이 아닌가요?

- **연산량 계량기입니다**: 명령어 한 줄, 반복문 한 바퀴, 배열 초기화와 복사마다 정해진 양의 Fuel이 차감됩니다. 똑같은 코드와 똑같은 `--fuel` 값을 주면 매번 정확히 같은 지점까지 돌고 끝납니다.
- **실제 시간 제한(타임아웃)이 아닙니다**: "몇 밀리초 안에 끝내라"가 아니라 "연산을 몇 단위까지 할 수 있다"를 셉니다.
- **OS 보안 샌드박스가 아닙니다**: 무한 루프를 막아 줄 뿐, 프로세스 권한 격리 같은 OS 수준 격리(`--isolated`)와는 다른 문제입니다.

## 기본값 `256`과 배열에서 큰 값이 필요한 이유

`--fuel`을 안 적으면 기본값 `256`이 들어가고, 최대 `16,000,000`까지 지정할 수 있습니다.

- `examples/answer.brc`나 `branches.brc`처럼 짧은 숫자 계산은 `256`으로도 충분합니다.
- `examples/loops.brc`처럼 반복 횟수가 많은 코드는 `--fuel 1000` 정도를 줘야 끝까지 돕니다.
- **배열·구조체 코드**: `main()`에 들어가기 전에 64 KiB 배열 공간을 준비하면서 **`65,537` Fuel**을 씁니다. 그래서 배열이 들어 있는 코드는 `--fuel 100000` 이상(중첩 구조체나 가변 슬라이스가 많으면 `--fuel 1000000`)을 주어야 합니다.

## Fuel이 다 떨어지면 어떻게 되나요?

실행 도중 Fuel이 바닥나면 VM은 중간에 계산하던 애매한 값을 돌려주지 않고 즉시 멈춥니다.

1. 프로세스 종료 코드 `5`로 끝납니다.
2. `--json`으로 실행했다면 `"status":"error"`, `"return_i32":null`, 그리고 `"error":{"kind":"fuel","byte_offset":...}` 형태로 어느 위치에서 멈췄는지 알려 줍니다.

```json
{"schema":"browniec.result/v1","profile":"brownie.m1-scalar/1","command":"run","status":"error","return_i32":null,"error":{"kind":"fuel","byte_offset":188}}
```

## 함께 기억해 둘 실행 한계

- **호출 깊이**: 함수 중첩 호출은 최대 `32`단계까지 가능합니다(`frame_limit`).
- **단일 파일 크기**: 소스 파일은 UTF-8 기준 `4096`바이트까지만 받습니다.
- **산술/배열 오류**: 오버플로(`overflow`), 0으로 나누기(`zero_divisor`), 배열 범위 초과(`bounds`) 모두 호스트를 망가뜨리지 않고 종료 코드 `5`로 안전하게 멈춥니다.
